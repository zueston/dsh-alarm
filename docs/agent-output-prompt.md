# 报警提醒 · Agent 输出协议（可直接粘进 system prompt）

> 用途：把下面「规则块」整段粘到 agent 的 system prompt / 项目 `AGENTS.md` 里。
> 目标：**该响的一次不落（不漏报），不该响的一次不响（不误报）**。
> 判定实现在 `lib/alarm.js`（`parseAlarmTags` + turn 结束判定）；本文件是它的「输入端契约」。

---

## 规则块（从这里开始复制）

```text
【报警提醒输出协议】你用 DSH 的 dsh-alarm 插件与人协作。它按下面的**标签协议**判断事件：
只有你在这条回复里写出对应标签，它才提醒人；没写标签就一律不打扰人。别指望它去猜你的措辞。

R0 标签格式（严格）：
   每个标签必须**独占一行**、写在**这一轮最后一条回复的正文**里（不要放代码块、不要放思考链、
   不要放工具参数）。一轮最多发一个「事件标签」，没事就不发。行首行尾允许空白。
   可用标签只有这六个：
     [[ALARM:ASK]]              需要人裁决（同时必须真的调用 ask_user_question）
     [[ALARM:PLAN]]             需要人确认计划（同时必须真的调用 exit_plan_mode）
     [[ALARM:DONE]]             全部任务完成（同时必须真的调用 update_goal action=complete）
     [[ALARM:TEST:<任务名>]]    某任务已到「待人工测试」，请人回窗口实测
     [[ALARM:RESTART]]          这一轮的改动需要重启 DSH 才生效
     [[ALARM:STALLED]]          我停下来了，没有后续动作可做
   标签大小写必须完全一致；写成 [ALARM:...]、[[alarm:...]]、[[ALARM:TEST]]（缺任务名）
   都不算，等于没发。

R1 什么时候发什么：
   - 要人做选择 → 调 ask_user_question，并在同一条回复末尾写 [[ALARM:ASK]]
   - 要人确认方案 → 调 exit_plan_mode，末尾写 [[ALARM:PLAN]]
   - 全部任务真的完成了 → 调 update_goal(action=complete)，末尾写 [[ALARM:DONE]]
   - 需要人实测 → 末尾写 [[ALARM:TEST:<任务名>]]（任务名用可读短名，不带路径）
   - 需要重启 DSH 才生效 → 末尾写 [[ALARM:RESTART]]（不要再靠正文措辞，插件只认标签）
   - 你没有可继续做的事、又不需要人操作 → 末尾写 [[ALARM:STALLED]]
   （后两种由插件在轮次结束时读取；其余标签是「给人看的副本」，事件本身仍由工具调用触发。）

R2 合并测试批次（用户说「先放着，一起测」时）：
   - 单个包照常推进，但**不要**在每个包结束时发 TEST 标签；
   - 全部包开发完后，发**一个** TEST 标签，任务名写批次，例如 [[ALARM:TEST:批次-2026Q4]]；
   - 插件侧还有聚合窗口：窗口内多发的 TEST 会被合并成一条汇总，别靠刷屏。

R3 标签与正文的关系：正文照常写人话（结论、下一步、请人做什么），标签只是**机器信号**，
   放在最后一行即可；不要用标签代替解释。

R4 禁止：伪造标签（没有对应事件却发标签）、一轮发多个事件标签、把标签埋进代码块或引号里、
   用标签绕过节流重复刷提醒。标签会写进诊断日志，伪造等于污染事实。

R5 收尾自检（发之前过一遍）：
   ① 这一轮真的发生了需要人知道的事件吗？没有就别发标签。
   ② 标签是否独占一行、拼写大小写完全正确、TEST 带了任务名？
   ③ 对应工具是否真的调用了（ASK/PLAN/DONE 三个必须调工具，标签只是副本）？
   ④ 是否一轮发了多个事件标签？只留最重要的一个。
   ⑤ 正文里是否写清了「请你做什么 + 怎么回话」？
```

## 附 A：判定模型（给人看的，不用粘进 prompt）

| 层 | 依据 | 说明 |
|---|---|---|
| 标签（主） | `parseAlarmTags()` 解析最后一条 assistant 正文里的独占行标签 | `RESTART` / `TEST:<任务名>` / `STALLED` 直接触发对应报警；`ASK` / `PLAN` / `DONE` 只记 `{ev:'tag'}` 日志（真正的触发在工具调用处） |
| 工具（辅） | `ask_user_question`、`exit_plan_mode`、`update_goal(action=complete)` | 与标签无关，始终生效 |
| 启发式（旧模式） | 正文正则判重启、状态文件相位判待测 | **仅当「严格协议模式」关闭时**才启用 |

### 为什么改成标签

旧方案靠猜措辞（正则、否定句、未来时、代码块过滤），必然两头出错：说「先不用重启」偶尔被当成要重启，说「等会儿要重启」又来不及。改成协议后，**说不说标签由 agent 决定，插件只做机械判定**，误报/漏报都归零；也顺手解决了「批量测试」要在插件里配一堆字段的问题——批次收尾发一个 TEST 标签即可。

## 附 B：设置项（设置页 →「批量测试协调」）

- **严格协议模式**（默认开）：只认标签；关掉后兼容旧的正文措辞与状态文件相位监视。
- **待测提醒聚合窗口（秒）**：把窗口内多个 TEST 标签合并成一条汇总（`0` = 每个都响）。
- **汇总附待测清单**：汇总时列出全部任务名。

## 附 C：缓存与去重

同 kind 4 秒节流；裁决后 15 秒闩锁；同一任务名 5 分钟去重；`stalled` 同 agent 10 分钟去重；同一状态文件 5 分钟去重（旧模式）。

## 附 D：最短可用版（空间紧张时只粘这 6 行）

```text
报警提醒：需要人时在回复最后一行写标签（独占一行、大小写一致、一轮只写一个）：
[[ALARM:ASK]] 要人裁决（并真的调 ask_user_question）／[[ALARM:PLAN]] 要人确认计划（并调 exit_plan_mode）
[[ALARM:DONE]] 全部完成（并调 update_goal action=complete）／[[ALARM:TEST:任务名]] 要人实测
[[ALARM:RESTART]] 需要重启 DSH／[[ALARM:STALLED]] 我停下来了、没有后续动作
没有事件就不写标签；标签别放代码块里；批量测试在收尾时写一个 [[ALARM:TEST:批次名]]。
```
