# AI Agent 输出关键词铁律（dsh-alarm 配套）

> 目的：让「报警提醒」插件能**准确**识别你想表达的事件——该响的响一次，不该响的绝不打扰人。
> 适用范围：所有会通过 DSH 与人类对话的 agent（含子代理）。本文件是**约束**，不是建议。
> 判定实现见 `lib/alarm.js`，本文每条规则后面都标了对应代码行，改判据时请同步改本文。

---

## 〇、三条总则（违反任意一条，判定必然出错）

1. **信号必须落在「正文」里。** 插件只读**该轮最后一条 assistant 消息**中 `type === "text"` 的正文片段。
   - 思考链（`reasoning` / `thinking`）、`tool-call` 参数、工具返回、代码块围栏（```` ``` ````）内的文字**一律不算**。
   - 也就是说：你在推理里写「现在可以重启 DSH」不会有任何提醒；写在正文里才会有。
2. **能用工具表达的，不要用文字表达。** 裁决、计划确认、任务完成都有专用工具（见第一节），靠文字描述不会触发对应提醒——只会被当成普通文本。
3. **一条消息只承载一个结论。** 同一轮里既有「请重启」又有「已有裁决待处理」时，报警会互相压（同 kind 4 秒节流、裁决后 15 秒闩锁），人只会收到一条。

---

## 一、六类事件：唯一合法表达方式

| 事件（报警标题） | 唯一合法触发方式 | 用文字说会怎样 |
|---|---|---|
| **需要你的裁决** | 调用 `ask_user_question` 工具（`lib/alarm.js:75` 起 `TOOL_KINDS`） | 只是普通文本，不响 |
| **需要你确认计划** | 调用 `exit_plan_mode` 工具 | 同上 |
| **全部任务完成** | 调用 `update_goal`，且 `action = "complete"`（唯一入口，`lib/alarm.js:1319` 起） | 「任务都完成了」写在正文里**不会**响；普通轮次结束也不会响 |
| **任务到「待人工测试」** | 把任务包状态文件 `<项目>/03-开发协同/<任务>/状态.md` 的 `当前阶段` 改成 `待人工测试`（`lib/alarm.js:179-186, 1236-1310`） | 正文里写「已到待人工测试」**不会**响；在命令行里 echo 这段话也不会 |
| **需要重启 DSH** | 在**最后一条回复正文**里写符合第三节句式的肯定句（`lib/alarm.js:157-169, 791-794`） | 写在思考链、工具参数、代码块里都不算 |
| **本轮结束 / 本轮中断 / 本轮报错** | 由这一轮**怎么收尾**决定，不可用文字伪造：`turn/end` 的 `reason` 为 `completed` → 本轮结束；命中 `/abort|interrupt|cancel|stop|user/i` → 本轮中断；其余 → 本轮报错（`lib/alarm.js:154`） | 与文本无关；这三项默认关闭 |

> **禁止伪造**：不要为了「让报警响」去写假的 `当前阶段：待人工测试`、不要空转调用 `update_goal(complete)`。报警会写进诊断日志与进度台账，伪造等于污染事实记录。

## 二、状态文件铁律（「待人工测试」专用）

1. 只有 `03-开发协同/<任务>/状态.md` 这种路径的写入会被跟踪（`isTaskStatusPath`）；写在别的文件里无效。
2. 判定看**文件相位的真实变化**，不看写入内容：
   - 写之前读到的 `当前阶段` ≠ `待人工测试`，写之后（1.2 秒复读）== `待人工测试` → 响一次；
   - 写前已经是 `待人工测试` → 不响（同值重写不算推进）；
   - 同一路径 5 分钟内只响一次（修复轮再次回到该阶段会再响，因为间隔远大于 5 分钟）。
3. 相位行格式：`当前阶段：待人工测试`（全角或半角冒号都认，行首允许 `>`/`*`/`#`/`-`/空格装饰）。字段名必须是「当前阶段」，不能只写「待人工测试」四个字。
4. 先用命令行拼脚本、再执行的方式同样有效——插件跟踪的是**工具调用**（`write`/`edit`/`pwsh`/`bash`）与**文件最终状态**，命令文本里出现路径只是线索，不作为判定依据。

### 2.1 合并测试批次（「先放着，一起测」）

任务包多、要先开发完再统一实测时，按下面约定执行，否则会「每个包各响一次」：

1. 单个包**照常**把 `03-开发协同/<任务>/状态.md` 的「当前阶段」写成 `待人工测试`（不绕开规范、不影响台账）。
2. 同时维护**唯一一个批次锚点文件**，路径里带批次锚点关键词（默认 `批次`），例如
   `03-开发协同/批次-2026Q4/状态.md`。
3. 插件侧二选一（设置页「批量测试协调」）：
   - **待测提醒范围 = 仅批次锚点**：只有锚点文件翻到 `待人工测试` 时才响，单包的推进**静默**；
   - **待测提醒聚合窗口（秒）> 0**：第一个包立即响，窗口内其余包**不响**，窗口结束时汇总成一条「N 个任务待人工测试：…」。
4. 批次收尾时**必须**把锚点文件写成 `当前阶段：待人工测试`——这是那一次「该测了」的唯一信号；忘了写 = 人收不到提醒（漏报）。
5. 中途**不要**反复重写锚点文件：同文件 5 分钟去重 + 聚合窗口会把它吞掉，等于白写。

## 三、重启提醒铁律（最容易被误判的一条）

### 3.1 判定链（`restartHitOf`，`lib/alarm.js:789-794`）

```
正文 → ① 去掉围栏代码块 ```...``` → ② 去掉否定说法 → ③ 去掉未来时/条件句 → ④ 剩余文本匹配 RESTART_RE
```

### 3.2 必须说：三要素齐备

**动作词 + 对象 + 现在时**

| 要素 | 合法取值 |
|---|---|
| 动作词 | 重启 / 重新启动；英文 `restart` / `reload` |
| 对象 | `DSH` / `dsh` / `客户端` / `软件` / `程序` / `应用`；英文 `dsh` / `app` / `client`（`the` 可有可无） |
| 现在时 | 现在可以… / 请… / 需要… / …后生效 |

**推荐句式（任选，写在最后一条回复的正文末尾）**

- `现在可以重启 DSH。`
- `请重启 DSH 后按下面 3 步验证。`
- `改动需要重启 DSH 才生效。`
- `重启客户端后生效。`
- `Restart DSH to apply.`

**简写也认**（`RESTART_RE` 的独立分支）：`需要重启`、`请重启`、`重启后生效` 单独成句即可命中。

### 3.3 禁止说：以下四种写法一定不响（或被过滤）

1. **否定式**（`NEGATED_RESTART_RE`，`lib/alarm.js:161-162`）
   不允许：`不需要重启`、`无须重启`、`无需重启`、`不必重启`、`不用重启`、`不要重启`、`别重启`、`勿重启`、`暂不重启`、`先不重启`、`不能重启`、`不会重启`、`不打算重启`、`不准备重启`。
   → 想说「这次不用重启」是合法的（会被过滤掉，不响）；但**别在同一句里同时出现肯定和否定**，否则以过滤后的剩余文本为准，容易谁都不命中。
2. **未来时 / 条件句**（`FUTURE_RESTART_RE`，`lib/alarm.js:165-166`）
   不允许：`等改完再重启`、`待会儿重启`、`再通知你重启`、`通知你重启`、`告诉你重启`、`稍后重启`、`之后重启`、`回头重启`、`改完重启`、`完成后重启`、`收尾后重启`、`搞定后重启`。
   → 这些句式会被整段摘掉。真要提醒人重启，**不要加时间状语**，直接说「现在可以重启 DSH」。
3. **围栏代码块里**（`FENCED_CODE_RE`，`lib/alarm.js:169`）
   ```` ```…重启 DSH…``` ```` 整块会被剔除——文档/脚本示例里的重启说明不算「这一轮在叫人重启」。
4. **思考链 / 工具参数里**
   推理段落与 `tool-call.arguments` 不参与判定；只有最终正文算。

### 3.4 一轮多提

同一轮里既提到「重启」又提到「不需要重启」，按 ②③ 过滤后的剩余文本判定；为免歧义，**一轮只保留一处重启相关表述**（要么肯定一次，要么否定一次）。

## 四、优先级与去重（同一轮多事件时）

| 优先级 | 规则 | 代码 |
|---|---|---|
| 1 | **重启命中即取代「本轮结束」**：同一轮不会又响重启又响结束 | `lib/alarm.js:1427` 起 |
| 2 | **`update_goal(complete)` 当场响，本轮 `turn/end` 不再补响** | `completedTurnSent` 去重 |
| 3 | **裁决/计划之后 15 秒内**的结束类提醒被闩锁吞掉（同一件事不响两次） | `askLatchSeconds`（默认 15） |
| 4 | 同 kind 4 秒内只响一次 | `throttleSeconds`（默认 4） |
| 5 | 同一状态文件 5 分钟内只响一次 | `AWAITING_TEST_DEDUPE_MS`（`lib/alarm.js:172`） |

**推论**：连续两条消息都写「请重启 DSH」，人只会收到一次；不要用重复刷屏来「确保它响」。

## 五、发布前 6 问（每条收尾消息过一遍）

1. 这件事有专用工具吗（裁决 / 计划确认 / 任务完成）？→ 用工具，别用文字。
2. 我这轮**最后一条正文**里，结论句是否完整落在正文（不是思考链、不是代码块）？
3. 重启类表述是否「动作词 + 对象 + 现在时」三要素齐备、且没有否定/未来时污染？
4. 如果我说「任务到待人工测试」，我是否**真的**把 `状态.md` 的 `当前阶段` 改成了 `待人工测试`？
5. 同一轮是否承载了两个以上结论？（是则拆成两轮，或只保留最重要的一个）
6. 我是否在用重复表述「刷」提醒？（不必要，节流会吞掉）

## 七、最小示例（可直接照抄）

**要人重启时（正确）**

```
改动已落地并自测通过，现在可以重启 DSH。
重启后请点侧栏「报警提醒」→ 条件表里点任意一行的 ▶ 试听。
```

**不要人重启时（正确处理：给否定句，让它被过滤，而不是模糊表述）**

```
这次是纯前端文案调整，不需要重启 DSH，刷新页面即可。
```

**任务推进到待人工测试时（正确）**

改 `03-开发协同/P-U2e-全站吸顶统一/状态.md`：

```
当前阶段：待人工测试
```

然后在对话里照常交付测试步骤即可（提醒由文件状态触发，不靠你复述）。
