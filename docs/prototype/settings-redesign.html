协议模式
默认模式 严格模式 ? 严格模式只认 agent 在回复里写的标签（[[ALARM:TEST:任务名]]、[[ALARM:RESTART]] 等），不再猜措辞——更准，但必须先点「编辑报警规则」把协议发给 agent，否则它会漏报：重启与待测都不会提醒。 默认模式 =插件自主判断，可不发协议，正文提到「要重启 DSH」、状态文件翻到「待人工测试」仍然会提醒。

默认模式：标签优先，没写标签时用旧判定兜底；严格模式：只认标签（需先发协议）。

什么时候提醒

一行一个条件：勾「提醒」表示这个条件会提醒，右边三列决定它用哪几条通道。表头那行是四条通道的总开关，关掉后所有条件都不走这条通道。 最后一列是该条件触发时的**播报文本**（留空即用默认，灰字就是默认值）。

批量测试协调

多个任务包先开发、最后一起实测时，用这里的规则把提醒收敛成一次。严格协议模式下，agent 用 [[ALARM:TEST:任务名]] 标签决定什么时候提醒。

待测提醒范围
「严格模式」下不生效。全部任务各自提醒 / 只提醒路径含「批次锚点」的那个状态文件。

状态文件路径里包含该片段才会提醒（不区分大小写），例如 批次、P-U2。严格模式下不生效。
