报警提醒
协议模式
默认模式 严格模式 ? 严格模式只认 agent 在回复里写的标签（[[ALARM:TEST:任务名]]、[[ALARM:RESTART]] 等），不再猜措辞——更准，但必须先点「编辑报警规则」把协议发给 agent，否则它会漏报：重启与待测都不会提醒。 默认模式 =插件自主判断，可不发协议，正文提到「要重启 DSH」、状态文件翻到「待人工测试」仍然会提醒。

默认模式：标签优先，没写标签时用旧判定兜底；严格模式：只认标签（需先发协议）。

什么时候提醒

一行一个条件：勾「提醒」表示这个条件会提醒，右边三列决定它用哪几条通道。表头那行是四条通道的总开关，关掉后所有条件都不走这条通道。

需要你确认计划（exit_plan_mode）
全部任务完成（任务级完成，不是每轮结束） 只在 agent 调用 update_goal（action=complete）时响；普通轮次结束不会响。
需要重启 DSH 严格模式下只认 [[ALARM:RESTART]] 标签；默认模式下正文提到「要重启 DSH」也会提醒。
任务到「待人工测试」 默认模式下按状态文件的真实相位变化识别；严格模式下只认 [[ALARM:TEST:任务名]] 标签。
每一轮结束都提醒 默认关闭；勾选后每轮跑完都响一次。默认不弹窗，避免每轮都打断。
本轮中断时提醒（手动打断）默认关闭。
本轮报错时提醒（异常结束）默认打开。
Agent 停下来且没有后续动作 一轮正常结束、但没调用任何工具也没请你裁决时提醒；默认开启。
手工测试提醒默认开启；取消后这一行的 ▶ 试听也不会响。
批量测试协调

多个任务包先开发、最后一起实测时，用这里的规则把提醒收敛成一次。严格协议模式下，agent 用 [[ALARM:TEST:任务名]] 标签决定什么时候提醒。

待测提醒范围
「严格模式」下不生效。全部任务各自提醒 / 只提醒路径含「批次锚点」的那个状态文件。
批次锚点关键词
状态文件路径里包含该片段才会提醒（不区分大小写），例如 批次、P-U2。严格模式下不生效。
